## Architecture Changes From May Alignment

- Added local SQLite off-chain metadata storage behind
  `deviceMetadataService`.
- New registrations store raw MAC and DID Document off-chain, and store hashes
  or references on Fabric.
- Added CIDR-aware IP context validation and membership checks.
- Split Fabric Gateway usage into application and administrator identity
  profiles in `fabricService`.
- Added `AuditLogContract` while preserving existing authentication-event
  state keys.
- Added global access-policy management through chaincode, backend routes, and
  a minimal dashboard page.
- Added optional signed device access token issuance after successful
  authentication.

## Consistency / Migration Strategy

The chosen compatibility strategy is temporary dual-schema support.

- Existing Fabric device records are left unchanged.
- New registrations use the May-2026 schema with `schemaVersion: "2026-05"`.
- Backend response merging enriches new records with off-chain metadata for
  dashboard display.
- Spoofing detection supports both new hash/CIDR records and legacy raw
  MAC/IP records.
- Registration writes the SQLite metadata first, then submits Fabric
  registration. If the Fabric commit fails, the off-chain metadata row is
  deleted to avoid an orphaned metadata record.

## Remaining Limitations

- `did:fabric` is project-specific DID-style syntax, not a formally registered
  W3C DID method.
- Verifiable Credentials are not implemented.
- Gateway peer failover is not implemented.
- MQTT is not implemented.
- Public Ethereum network testing was not performed.
- The RADIUS/LDAP comparison remains a controlled local baseline.
